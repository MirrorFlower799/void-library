# 虚空图书馆 V5：收藏库批量刮削、备份追加、独立刮削名称

日期：2026-10-12。以 V4 阅读器源码为基础，仅修改收藏库及其导入流程，继续保留 V4 的书库与阅读器功能。

## 1. 批量补全无封面收藏

入口：收藏库顶栏「🔍 批量补封面」。从 `games` 筛选 `cover` 为空的条目，不覆盖已有封面；逐条搜索、选图、下载、生成 640×360 的自动居中裁切封面，每张成功后立即落盘。任务具备日志、总量、进度和中止按钮；关闭窗口也会请求停止。当前网络请求结束后才停止，不支持强制中断已发出的图片下载。

- 查询名称优先取 `scrapeName.trim()`，为空时使用 `name`。
- 可手选 SteamGridDB / TMDB / Bangumi / VNDB，默认按收藏分类和平台自动选择。
- 只采用规范化后与查询名一致的搜索项（兼容一些空白和标点差异）。未匹配则跳过，避免将不相关封面覆盖进去；名称差异大的条目可自行设置准确的「刮削名称」再批量处理。
- 不改动收藏标题、评分、状态、截图和通关记录。
- 各刮削站点要求联网，SteamGridDB 和 TMDB 可能需要在应用设置中填写 API Key；如果搜索站点限流或拒绝服务，会记为失败而不是覆盖已有内容。

## 2. 导入：先预览，再选追加/覆盖

入口：收藏库顶栏「⬆ 导入」。打开 `.zip` 或旧版 `.json` 后先预览来源文件名、收藏/角色/书库数量，再选择：

- **追加（默认）**：按每条的稳定 ID 排除已存在记录，其余添加到现有收藏；角色同理。导入书架遇到 numeric ID 冲突时映射新书架 ID，并把导入书籍的 shelfId 一同映射。现有记录原样保留。
- **覆盖**：使用备份中的收藏记录替换当前收藏记录，并在备份确实包含角色或书库时一并替换对应数据。需要用户二次确认。
- **文件安全**：预览过程完全不写入图片/数据；确认后才写入。ZIP 里新增的图片复制时生成随机文件名，防止与当前封面、截图同名冲突；缺失的归档图片不关联到同名的旧本地文件。生成一次性 token，不能重复提交或以无效 token 应用数据。
- 旧 ZIP 和 JSON 数据布局继续接受。注意应用的 ZIP 备份只导出书库目录元数据/封面，不打包 `books` 里的原书文件，恢复时仍需单独保留 `books` 文件夹。

## 3. 独立刮削名称

添加/编辑弹窗第一行的「名称」右侧新增「刮削名称」文本框（可选，最多 160 字符）。保存到 `data.json` 的 `scrapeName` 字段，并随导入/导出保留。手动打开「在线刮削」时默认先搜索该字段；用户仍可以在弹窗里自由改写搜索词。旧记录没有 `scrapeName` 时默认空串，原有显示名称和数据字段不变。

## 核心文件

- `app/src/index.html`、`app/src/styles.css`：新入口及交互弹窗。
- `app/src/renderer.js`：表单、别名搜索、封面批处理、两阶段导入 UX。
- `app/src/models.js`：规范化保留 `scrapeName`。
- `app/preload.js`、`app/lib/ipc.js`：导入预览/提交 IPC。
- `app/lib/backup-import.js`：ZIP/JSON 解码、冲突合并、图片隔离复制。
- `test/backup-import.test.js`、`test-renderer.js`：后端和 UI 回归。

## 实际运行限制及数据安全

- 尚未在真实 Windows 图形环境进行人工操作和第三方在线刮削联网验收；自动测试使用模拟网络返回。部分站点的 API 或额度可能变动。
- 追加去重基于条目 ID，不会用同名自动合并，以避免把不同版本或平台的收藏误合并。不同 ID 的同名条目仍可追加。
- 建议更新前备份 `data.json`、`library.json`、`characters.json` 和图片目录 `covers/`、`shots/`、`chars/`、`bookcovers/`。先退出软件，然后替换 `resources/app.asar`；也可使用独立便携版。
- `books` 文件夹的实际书籍不包含在收藏库导出 ZIP 内，迁移必须单独保存。
