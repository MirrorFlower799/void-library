# 书库阅读器第二轮优化：滚轮、单双页与 PDF

更新日期：2026-10-12。此版本基于此前的阅读器性能优化源码继续修改；**没有更改用户书库数据的 JSON 格式、书籍路径、阅读记录字段或 Electron IPC API**。

## 1. 滚轮与翻页延迟

**问题定位**

- 主界面 `renderer.js` 的滚轮监听使用 `260ms` 固定冷却；Foliate `paginator.js` 的翻页内部还增加 `100ms` 人为等待。
- 在嵌套的 Foliate 章节 iframe 内滚动时，`wheel` 事件不会冒泡到外层主界面；一些位置滚轮无法触发外层翻页。
- PDF 页面加载使用串行阶段，页面内容未准备好时用户会感到点击无响应。

**实现**

- 删除 260ms / 100ms 人为等待；每次首个有效滚轮事件立即触发一次导航。为避免触控板每个微小滚动输入都翻页，累积小的 delta，保留短暂 90ms 的防连翻间隔。此间隔不是翻页前的等待；第一次操作不会被它延迟。
- 在主界面和 Foliate 内容文档分别监听 `wheel`，分页状态内部拦截滚轮，滚动状态 EPUB/TXT 继续使用其原生滚动行为。PDF/固定版式没有原生连续滚动，因此即使切换了滚动按钮，滚轮仍逐页翻动。
- 保留异步导航队列，避免 PDF 载入期间连续点击导致旧加载结果覆盖新页面；添加有上限的滚轮请求积压控制。
- Foliate 章节切换的锁通过 `finally` 释放，避免读取/排版异常后长期无法翻页。

## 2. 新增单双页

- 底部新增「单页 / 双页」按钮，选择保存在 `localStorage`（若浏览器环境拒绝访问存储，仍可在当前运行期间使用）。
- EPUB/MOBI/FB2 等流动排版：修改 Foliate 排版器的 `max-column-count`；在窗口过窄或滚动排版时仍遵循内核的单列约束。
- PDF 与固定版式：动态重建单页/双页页组，切换后恢复当前章节/页索引。左右 PDF 页面及 iframe 使用并发载入。
- 漫画/图片序列（包括 ZIP/CBZ 等）：双页并排，前进/后退每次移动一组，奇数末页保留单张，进度与页数提示对应更新。
- TXT 保留原有连续滚动和文字选择能力，未强行改成分页排版。

## 3. PDF 加载优化

修改 `app/book/vendor/foliate-js/pdf.js` 和 `fixed-layout.js`：

1. 首屏高 DPI 画布像素数量上限由约 800 万降至约 400 万，DPR 最大 1.5；减少图形内存分配和主线程绘制压力。极高倍缩放与复杂矢量页仍可能耗时。
2. 先渲染/显示页面画布，再通过 idle callback 延后创建可选文字、注释链接层。保留文字选中、搜索所需的文本层，而不是为了加速直接删除这些功能。
3. 使用有限的 `ImageBitmap` LRU 缓存，目标像素容量约 1200 万像素（约 48MiB RGBA），返回已打开页可直接复制位图，减少重复 PDF.js 渲染。没有 `createImageBitmap` 的环境会正常回退。
4. 预热相邻页的 PDF 页面对象；PDF 元数据和目录解析并发；保留原有 HTTP Range 按需读取，并明确关闭 PDF.js 额外的自动流预取。
5. 在切页时取消已废弃文档的渲染任务、文本层以及 idle 操作。
6. **双缓冲页面替换**：旧的可见 PDF 页保持显示，新的 iframe 在隐藏位置加载、绘制；只有新页面画布准备好之后才移除旧页面，减少翻页闪白。PDF 左右页画布并行绘制。

## 4. 验证与已知限制

运行：

```bash
npm run check
npm test
npm run build
# Windows 便携包（需提供原版 Electron 运行时）
VOID_LIBRARY_RUNTIME=/path/to/runtime npm run build:portable
```

- Node 层全部 24 项回归通过（含新增的导航、页面布局、双缓冲、PDF 先绘制与旧任务取消专项测试）。
- ZIP/日期基础测试 12/12 通过。
- jsdom 界面测试 214/214 通过，其中新增单双页按钮、漫画双页、奇数尾页及按钮前后翻页回归。
- `app.asar` 使用原构建脚本逐文件校验 SHA-256/字节内容。

**限制**：当前环境尝试了系统 Chromium 无头浏览器的本地 HTTP 回归，但浏览器访问被环境策略返回 `ERR_BLOCKED_BY_ADMINISTRATOR`，因此未能完成真实 Chrome/Electron GUI 的 PDF 页面首屏计时和帧率对照。不能把上述改动宣称为实测提升了某个固定百分比，也不保证复杂矢量、大型扫描 PDF 所有页面完全不卡顿。请在 Windows 实机重点检查双页、长时间阅读、文字选择、目录链接、超大 PDF、不同 DPI/缩放下的效果。

**兼容性**：原有书库和进度数据不需要迁移。若新应用仍出现特定 PDF 页面缓慢，提供能复现的 PDF 样本及页码，才能进一步按具体的字体、图片解码或矢量内容进行 Profile。参考 PDF.js 官方范围加载文档：<https://mozilla.github.io/pdf.js/api/draft/api.js.html>，参考 Foliate-js 固定布局结构：<https://github.com/johnfactotum/foliate-js>。
